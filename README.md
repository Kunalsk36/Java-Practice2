## 📚 Practice Approach

The learning roadmap is organized **day-wise**, with the difficulty increasing gradually.

However, the repository itself is organized **session-wise**.

This distinction is intentional.

The **roadmap Day** represents the recommended learning progression, while a **Session** represents an actual practice session.

For example:

```text
Day 1 → Basic Java
Day 2 → Input and Operators
Day 3 → Conditions
Day 4 → Loops
```

My actual practice may look like:

```text
Session01 → Day 1 + some Day 2 questions
Session02 → remaining Day 2 + some Day 3 questions
Session03 → Day 3 + Day 4 questions
```

A session may therefore cover one or more roadmap days depending on my pace, understanding, and the amount of practice completed.

The goal is **not to rush through the roadmap**.

The goal is to understand the concepts, build logic, and gradually increase the difficulty.

# 🧠 Daily Practice Method

For every problem, I will try to follow this process.

## 1. Understand the Problem

Before writing code, identify:

- What is the input?
- What is the expected output?
- What conditions are involved?
- What logic is required?

---

## 2. Think Before Coding

I will first try to develop the solution in my own words.

I should be able to roughly explain:

```text
What do I need to do?
What variables do I need?
What steps should happen first?
What should happen next?
```

Only after that should I start coding.

---

## 3. Write the Java Program

Implement the solution myself instead of immediately copying an existing solution.

The goal is to develop independent problem-solving ability.

---

## 4. Test the Program

I will test programs using different inputs.

For example:

- Normal inputs
- Small values
- Large values
- Boundary cases
- Special cases
- Invalid inputs when applicable

---

## 5. Understand the Solution

After solving a problem, I should be able to explain:

- Why the logic works
- What each important statement does
- Why particular variables are required
- What happens during execution
- The time and space complexity when relevant

---

## 6. Revise Difficult Problems

If I need help solving a problem, I should not simply consider it completed.

Problems that required significant help should be revisited later and solved again without looking at the previous solution.

# 💻 Java Source and Compiled Files

The repository may contain both:

```text
Program.java
Program.class
```

The `.java` file contains the Java source code.

The `.class` file contains the compiled Java bytecode generated by the Java compiler.

For example:

```bash
javac PrintHelloWorld.java
java PrintHelloWorld
```

The first command compiles the Java source file and generates the `.class` file.

The second command executes the compiled Java program.

In the future, compiled `.class` files may be excluded from Git using `.gitignore` if the repository is intended primarily for storing source code.

# 🗓️ Roadmap vs Practice Sessions

The Excel roadmap uses **Day 1, Day 2, Day 3...** to define the learning progression.

The GitHub repository uses **Session01, Session02, Session03...** to record actual practice.

They serve different purposes.

| Roadmap | Repository |
|---|---|
| Day 1 | Session01 |
| Day 2 | Session02 |
| Day 3 | Session03 |
| Recommended learning sequence | Actual practice history |
| What should be learned | What was actually practiced |
| Can take multiple sessions | Represents one actual session |

For example:

```text
Roadmap:

Day 1 → Java Basics
Day 2 → Input + Operators
Day 3 → Conditions
Day 4 → Loops


Actual Practice:

Session01 → Day 1 + Day 2
Session02 → Day 2 + Day 3
Session03 → Day 3 + Day 4
```

There is **no problem if one roadmap day takes more than one session**.

Understanding the concept is more important than following an artificial deadline.

The number of programs completed is less important than the quality of understanding.

### Rule 6 — Practice Consistently

Consistency is more important than completing a large number of programs in a short period.
